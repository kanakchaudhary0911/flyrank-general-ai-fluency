# Three Roads: Choose Your Stack with AI

## Assignment Overview

For this assignment, I used AI to compare three different ways of building my portfolio instead of immediately choosing the most powerful or familiar option.

The goal was to choose a stack based on my actual skill level, portfolio requirements, timeline, ability to maintain it, and how my work needs to be displayed.

---

## Objectives

- Compare three different approaches for building the portfolio.
- Evaluate each option against practical project requirements.
- Consider skill level, timeline, maintainability, and customization.
- Identify the trade-offs of each stack.
- Use AI to pressure-test the available options.
- Select the most practical stack for the current portfolio goals.

---

## My Constraints

- Free tools only
- Beginner/intermediate development skill level
- Portfolio focused on Backend Development, Web Development, and AI
- Must showcase projects and case studies
- Must display screenshots and visual evidence
- Must include GitHub repositories and live demo links
- Must be responsive and easy to update
- No backend required at launch
- Must be realistic to complete within two weeks

---

## Three Options Considered

### 1. No-Code

**Examples:** Notion + Super, Carrd, Wix, Framer

**Main benefit:** Fastest and easiest to launch.

**Main limitation:** Does not strongly demonstrate coding ability and provides less control over technical/custom layouts.

---

### 2. Plain HTML + CSS + JavaScript

**Tools:** HTML5, CSS3, JavaScript, Git/GitHub

**Hosting:** GitHub Pages

**Backend:** Not required at launch.

**Main benefit:** Provides a strong balance between technical credibility, simplicity, customization, and maintainability.

**Main limitation:** Less reusable and scalable than a framework such as React.

---

### 3. React

**Tools:** React, Vite, CSS/Tailwind CSS

**Hosting:** Vercel or Netlify

**Backend:** Not required at launch.

**Main benefit:** Reusable components, scalability, and strong framework-level frontend skills.

**Main limitation:** Higher learning curve, more tooling, and more maintenance than currently necessary.

---

## Final Decision

I chose **Plain HTML + CSS + JavaScript hosted on GitHub Pages**.

I chose this because it matches my current skill level and the actual needs of my portfolio. I can understand and explain the code myself while still having enough control to create project case studies, screenshots, GitHub links, live demo links, and responsive layouts.

I do not need a backend at launch because the portfolio only needs to present static content and provide contact/social links.

I rejected No-Code because it would not demonstrate my coding skills strongly enough. I rejected React because, although it is more scalable and reusable, it adds complexity that I do not currently need.

The main trade-off is that plain HTML/CSS/JS requires more manual updates and is less scalable than React. However, **I can maintain it myself**, and **it shows my work well**.

I can realistically finish and deploy this portfolio within two weeks, making this the most practical choice for my current goals.

---

## Backend Decision

**Backend required at launch: No**

A backend can be considered later if the portfolio needs dynamic features such as a custom contact form or other server-side functionality.
