# Three Roads: Choose Your Stack with AI

## My Portfolio Requirements

Before choosing a stack, I gave AI my actual constraints:

* Free tools only
* Beginner/intermediate skill level
* The portfolio should prove my Backend Development, Web Development, and AI skills
* It should showcase projects and case studies
* It should display screenshots/images
* It should include GitHub repositories and live demo links
* It should have Home, Projects, About, and Contact sections
* The portfolio should be easy to understand, explain, and maintain
* No backend is required at launch

---

# Option 1: No-Code

## Stack

Notion + Super, Carrd, Wix, or Framer free tier.

## How I Would Build It

I would use a visual website builder and create the portfolio using templates, drag-and-drop sections, and form-based editing without writing code.

## Free Hosting

Depending on the tool, the free plan can provide a hosted subdomain.

## Backend Required?

**No.**

## What I Would Need to Learn

Very little technical knowledge would be required. I would mainly need to learn how to organize content and customize the chosen template.

## How Well It Shows My Work

It can display basic projects, descriptions, images, and links, but it is less suitable for detailed technical case studies and highly customized layouts.

## Technical Skill Demonstration

**Weak.** Since the site is built without code, it would not strongly demonstrate my web development ability.

## Maintenance

**Very easy.** I could update content through the visual editor.

## Main Trade-Off

I would gain speed and simplicity but lose customization and technical credibility. For my goal of proving Backend, Web Development, and AI skills, this is a significant limitation.

---

# Option 2: Plain HTML + CSS + JavaScript

## Stack

* HTML5
* CSS3
* JavaScript
* Git/GitHub
* GitHub Pages for hosting
* AI assistance for boilerplate, debugging, copy, and design refinement

## How I Would Build It

I would create the portfolio using HTML for structure, CSS for styling and responsiveness, and JavaScript for small interactive features such as navigation, image galleries, or project filtering.

## Free Hosting

**GitHub Pages** or Netlify.

## Backend Required?

**No.**

The portfolio can remain a static website at launch.

## What I Would Need to Learn

* Semantic HTML
* CSS Flexbox/Grid
* Responsive design
* Basic JavaScript
* Git and GitHub
* Deployment using GitHub Pages

These are skills I am already developing, so this option reinforces my existing learning instead of introducing an entirely new stack.

## How Well It Shows My Work

**Good.** I can create custom project sections, case studies, screenshots, GitHub links, live demo links, and readable technical content.

## Technical Skill Demonstration

**Strong.** The portfolio itself becomes evidence that I understand web fundamentals and can build a working website.

## Maintenance

**Low to moderate.** I can directly edit the files and update projects myself. The main challenge is keeping repeated sections such as navigation and footer consistent across pages.

## Main Advantages

* Free
* Lightweight and fast
* Full control over design
* Easy to understand and explain
* Directly demonstrates coding ability
* Simple to deploy

## Main Disadvantages

* Less reusable than React
* More manual work when adding many projects
* No built-in component system
* Can become repetitive as the site grows

## Main Trade-Off

I trade some scalability and component reusability for simplicity, transparency, and easier maintenance.

---

# Option 3: React-Based Portfolio

## Stack

* React
* Vite
* CSS or Tailwind CSS
* React Router
* Git/GitHub
* Vercel or Netlify for hosting

## How I Would Build It

I would create reusable components such as Navbar, ProjectCard, CaseStudy, and Footer. Project information could be stored as structured data and rendered through reusable components.

## Free Hosting

**Vercel or Netlify.**

## Backend Required?

**No.**

React can be deployed as a static site, so a backend is not required at launch.

## What I Would Need to Learn

* JSX
* Components
* Props
* State
* React Router
* npm/build tools
* Component-based development
* Possibly Tailwind CSS

## How Well It Shows My Work

**Excellent.** It provides strong control over project layouts, reusable case-study components, and interactive features such as filtering.

## Technical Skill Demonstration

**Strongest for frontend/framework skills**, provided I genuinely understand the React code I build.

## Maintenance

**Higher upfront complexity.** Once properly built, reusable components make updates easier, but I would also have to manage dependencies, build tooling, and possible deployment/build errors.

## Main Advantages

* Reusable components
* Easier scaling to many projects
* Strong React/frontend skill signal
* Good path for future interactive features

## Main Disadvantages

* Steeper learning curve
* More setup and tooling
* Dependency management
* Higher risk of confusing build/deployment issues
* More complexity than my current portfolio actually requires

## Main Trade-Off

I would gain scalability and framework-level skills but take on extra complexity and maintenance that I do not currently need.

---

# Initial Comparison

| Option          | Simplicity | Technical Skill Proof | Customization | Maintenance  | Fit for My Current Needs |
| --------------- | ---------- | --------------------- | ------------- | ------------ | ------------------------ |
| No-Code         | Very High  | Low                   | Low–Medium    | Very Easy    | Low                      |
| HTML + CSS + JS | High       | Strong                | High          | Low–Moderate | **High**                 |
| React           | Medium–Low | Strongest             | Very High     | Moderate     | Medium                   |

## AI Recommendation

After comparing the three options, AI recommended **Option 2: Plain HTML + CSS + JavaScript hosted on GitHub Pages**.

However, the recommendation is not the decision by itself. I will make the final choice based on my own skill level, timeline, portfolio requirements, and ability to maintain the project.
