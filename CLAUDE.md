## 03 — Survive-the-Crit

The **Survive-the-Crit** assignment focused on reviewing the portfolio through external first-time-visitor feedback and using that feedback to make concrete improvements.

The review included a 10-second proof test:

1. **“10 seconds mein, main kya karta hoon?”**
2. **“Kya tumhe lagega ki main ismein achha hoon?”**

The reviewer identified the portfolio as a backend-focused technical portfolio and highlighted the SpellForge data-modeling decision as a strong technical signal.

### Key feedback addressed

- Make technical strengths immediately obvious.
- Clearly communicate backend and data-modeling strengths.
- Structure projects around clear problem, contribution, and result.
- Surface the SpellForge data-modeling decision.
- Clearly distinguish personal contribution from technologies used.
- Give more emphasis to concrete engineering decisions and outcomes.
- Make engineering ability easier to identify without requiring inference.

## Documentation Rule

When correcting or updating documentation:

- Preserve the original work.
- Fix inaccurate titles, folder references, structure descriptions, or status text.
- Do not invent project results, evidence, screenshots, links, or completion claims.
- Keep facts separate from recommendations or future plans.
- Use the actual repository structure as the source of truth.
- Keep README files concise, specific, and relevant to the folder they describe.
- Keep assignment names and folder names exactly as they exist in the repository.
- Update status text whenever the actual completion state changes.

---

## Evidence Principle

Every major claim about completed work should be supported by actual repository evidence whenever possible.

Preferred evidence includes:

- Source files
- README documentation
- Screenshots
- Screen recordings
- Build logs
- Prompt or decision logs
- GitHub history
- Live project links
- Form submission evidence

The repository should remain an accurate record of what was actually built, tested, documented, and submitted.

## AI-Assisted Development Principle

AI tools may be used to accelerate:

- Planning
- Implementation
- Debugging
- Documentation
- Research
- Workflow design

However, generated work should be reviewed and understood before being treated as final.

The repository should document important implementation decisions and preserve human understanding and control over the final result.
