---

## Structure Rules

- Use `Week-01`, `Week-02`, etc. for weekly grouping.
- Keep the existing assignment folder names unchanged.
- Each assignment folder should contain assignment-specific documentation and evidence.
- Use `README.md` for the main human-readable explanation.
- Keep focused artifacts such as prompts, logs, decisions, and checklists in separate files.
- Keep screenshots, recordings, and other evidence inside the assignment folder they support.
- Never add fabricated or placeholder evidence.
- Preserve real evidence when updating documentation.
- Keep documentation aligned with the actual completion status of each assignment.

## Future Work

Future weeks and assignments should be added using the same evidence-first structure.

For new work:

- Create the assignment inside the appropriate weekly folder.
- Keep assignment-specific evidence with that assignment.
- Add a clear README describing the work.
- Document important decisions and implementation changes.
- Update the relevant weekly README when the assignment is completed.
- Update the root README progress table when a week changes status.
- Do not mark future work as completed until the actual work and evidence exist.

---

## Documentation Rule

When correcting or updating documentation:

- Preserve the original work.
- Fix inaccurate titles, folder references, structure descriptions, or status text.
- Do not invent project results, evidence, screenshots, links, or completion claims.
- Keep facts separate from recommendations or future plans.
- Use the actual repository structure as the source of truth.
- Keep README files concise, specific, and relevant to the folder they describe.

---

## Evidence Principle

Every major claim about completed work should be supported by actual repository evidence whenever possible.

Preferred evidence includes:

- Source files
- README documentation
- Screenshots
- Screen recordings
- Build logs
- Prompt or decision logs
- GitHub history
- Live project links

The repository should remain an accurate record of what was actually built, tested, documented, and submitted.
