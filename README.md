### FL-13 — Ship an Automation Workflow v2
**Status:** ✅ Completed

Built a repeatable AI-assisted writing workflow in Claude Projects using structured stages:

```text
Rough Input
    ↓
  Draft
    ↓
Critique
    ↓
Final Revision
    ↓
Human Check
```

The workflow was tested on five real inputs:

1. Student Performance Analysis
2. AI Internship Landing Page
3. Why Database Design Matters
4. Mentor Feedback Email
5. SpellForge

The workflow focused on:

- Preserving factual accuracy
- Avoiding unsupported claims
- Improving clarity and structure
- Maintaining appropriate tone
- Identifying missing information
- Producing revised final outputs
- Clearly identifying human verification requirements

The five-run retrospective identified limitations including over-structured drafts, mechanically repeated critique categories, incomplete prioritization of missing information, and the continued need for human verification of project-specific details.

**Time per run:** approximately 10–15 minutes.

### FL-14 — Agent Concepts and MCP Basics
**Status:** ✅ Completed

Explored the distinction between AI workflows and agents and learned the fundamentals of the Model Context Protocol (MCP).

Connected Google Drive to Claude using the available connector integration and used the connected tool to perform tasks involving external files.

**MCP Evidence**

The connected Google Drive integration was used for tasks that required access to external Google Drive data rather than relying only on chat context.

The workflow included:

1. Google Drive search for files related to FlyRank and AI Fluency.
2. Reading a file directly from Google Drive using the connected integration.
3. Comparing information from retrieved Google Drive files based on their actual contents.

The connector demonstrated that Claude could retrieve and work with external Google Drive information through a tool connection.

**Agent and Workflow Understanding**

The FL-14 work also examined how a fixed workflow differs from an agent.

The FL-13 workflow follows predefined stages:

```text
Input
  ↓
Draft
  ↓
Critique
  ↓
Revision
  ↓
Human Check
```

This makes FL-13 a structured workflow rather than a fully autonomous agent.

An agent version would require the system to dynamically decide which actions or tools to use, determine the next step based on intermediate results, and work toward a goal with greater autonomy.

**Evidence**

Evidence for the MCP and Google Drive connector work is stored in:

`04_FL-14_Agent_Concepts_and_MCP_Basics/screenshots/`

The screenshots document the connector setup, Google Drive searches, permission/tool-call steps, and retrieved results.
