## Portfolio Positioning

### Primary Technical Claim

I design data models that anticipate future features and make the engineering tradeoffs behind them explicit.

### Target Hiring Person

**Backend Engineering Lead** evaluating entry-level backend talent for long-term engineering potential.

### Primary Action

Review the **SpellForge/Reikein** GitHub repository and the engineering reasoning documented around its database design. If the approach is a fit, reach out.

The portfolio follows an **evidence-first** approach: show credible technical proof before asking for contact.

## One-Line Claim

> **I design data models that anticipate future features and make the engineering tradeoffs behind them explicit.**

This is the portfolio-facing version of the positioning developed in **What Are You Proving**. It keeps the claim specific to data modeling and engineering reasoning rather than using a generic developer statement.

## CTA Ladder

The portfolio follows an evidence-first path:

**Home → Featured Proof → Case Study → Repository / Technical Reasoning → Contact → Reach Out**

The portfolio should not push contact before showing credible evidence.

The case study and repository provide the proof first; outreach is the final action.
