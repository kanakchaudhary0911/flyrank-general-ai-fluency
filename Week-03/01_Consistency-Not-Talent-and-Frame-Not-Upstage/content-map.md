# Content Map

## Portfolio Through-Line

The portfolio is structured around one central proof:

> **I design data models that anticipate future features and make the engineering trade-offs behind them explicit.**

The portfolio should show this proof before asking the visitor to take the final action.

---

## 1. Home

### Purpose

Give the visitor an immediate understanding of what I prove and direct them toward the strongest technical evidence.

### Sections in Order

1. **Hero**
   - One-line claim
   - Short supporting statement
   - Primary navigation

2. **Proof Introduction**
   - Brief explanation of the type of backend engineering work I focus on
   - Emphasis on data modeling and engineering reasoning

3. **Featured Case Study**
   - **SpellForge / Reikein**
   - Lead with the strongest technical proof

4. **Selected Projects**
   - AI Internship Landing Page
   - Student Performance Analysis
   - Other relevant projects only if they strengthen the main positioning

5. **Technical Capabilities**
   - Backend development
   - Database design
   - Python / data work
   - Web development
   - AI-assisted development

6. **Final CTA**

### Primary CTA

**Review the SpellForge / Reikein Case Study**

### Secondary CTA

**View Selected Projects**

## Featured Case Study Structure — SpellForge / Reikein

The case study should present the engineering reasoning clearly rather than only showing the final interface.

### Sections

1. **Problem**
   - What problem the project addresses

2. **What I Built**
   - Project overview
   - Main functionality

3. **Architecture / System Context**
   - How the major parts of the system relate

4. **Database Design**
   - Main entities
   - Relationships
   - Data-model structure

5. **XP History Design Decision**
   - Explain why XP history is represented separately from the user's current progression

6. **Engineering Trade-off**
   - Explain the reasoning behind the design
   - Discuss normalization, traceability, and query simplicity where relevant

7. **Why This Approach**
   - Explain how the design anticipates future features

8. **Technical Stack**
   - Technologies actually used in the project

9. **Repository / Demo**
   - GitHub repository
   - Live demo, if available

10. **Future Improvements**
    - What could be improved or extended next

### Primary CTA

**Review the SpellForge / Reikein Repository and Design Reasoning**

### Final CTA

**Get in Touch**
