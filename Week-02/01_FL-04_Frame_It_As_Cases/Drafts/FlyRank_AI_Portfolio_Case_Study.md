# Case Study: FlyRank AI Engineering Portfolio

**Audience:** Recruiters hiring for Backend Developer and Software Development Internship roles

## The Problem

My internship work was scattered. Assignments, notes, and documentation were spread across different files and folders with no clear structure. There was no single place where someone could look at my work and understand what I had actually done or how I approached it. I wanted to fix that by building one organized, professional space for my FlyRank AI Fluency internship work.

## What I Did

I created a dedicated GitHub repository and organized my internship work week by week. Each week has its own folder. Inside each folder, I added the assignment files, a README explaining the task, and screenshots where relevant.

I wrote a separate README for each assignment instead of one big file covering everything. I used Git and GitHub to manage versions and track progress over time. I also used Claude and ChatGPT to help sharpen my documentation and think through how to structure the repository so it made sense to someone reading it for the first time.

## Decisions I Made

I chose a week-by-week structure so any assignment could be found quickly without digging through unrelated files. Each folder holds only what belongs to that week — the assignment, its README, and supporting screenshots.

I kept the README format consistent across every assignment. Same structure, same tone, every time. This made the repository easier to scan and gave it a more professional feel instead of looking like a pile of separate, unrelated files.

I also made a call to only include work I had actually finished and documented properly. I left out incomplete work and unnecessary files, even if that meant fewer folders in the repository.

## Challenges

As the number of assignments grew, keeping the structure clean got harder. I had to settle on a folder naming convention and stick to it, or the repository would have turned messy fast.

The bigger challenge was the writing itself. My first drafts of the READMEs read like generic AI output — vague, overly polished, not like something a real person would write. I went back and rewrote them several times until they sounded like me actually explaining my work, not a templated summary.

## Outcome

The repository is now a structured, organized record of my AI Fluency internship work. Every week has its own documented folder with a README, files, and screenshots. Instead of scattered work across random locations, it's all in one place and easy to review. It also gives me a base I can keep adding to as I take on more projects.

## What I'd Do Differently

I'd plan the folder structure in more detail before adding any files, instead of adjusting it as the repository grew. I had to reorganize a few folders and rewrite some documentation partway through because I hadn't thought the structure through from the start.

Going forward, I want to add more real projects to the repository, include live demos where I can, and keep refining the documentation so it stays clear and easy to navigate as it grows.
