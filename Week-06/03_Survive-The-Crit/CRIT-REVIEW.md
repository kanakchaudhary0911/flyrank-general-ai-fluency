# Crit Review

## Assignment

**Survive the Crit**  
Week 6 — General AI Fluency

## Purpose

This review was conducted to evaluate the portfolio from a first-time visitor's perspective and identify whether the portfolio clearly communicates what I do and provides enough evidence of my engineering ability.

The reviewer was given my Week 1 proof statement before reviewing the portfolio.

---

## 10-Second Proof Test

### Question 1

**“10 seconds mein, main kya karta hoon?”**

### Reviewer Response

> My first impression is that you’re a backend developer with an interest in AI, and you’re focused more on building the logic/data side of applications than just the UI. The portfolio gives me a technical/developer impression rather than a general “I can build websites” impression.

### Question 2

**“Kya tumhe lagega ki main ismein achha hoon?”**

### Reviewer Response

> Yes, I would be reasonably confident that you’re technically strong, especially on the backend/data-modeling side. The SpellForge example is actually a good signal because separating XP History from the current progression shows that you’re thinking about data integrity, auditability, scalability, and future features rather than just making the current feature work.

---

## Additional Reviewer Feedback

The reviewer provided the following feedback:

- The biggest improvement would be making the technical strengths immediately obvious.
- Within a few seconds, the portfolio should communicate what kind of backend work I am particularly good at.
- Projects would be stronger if each clearly showed **Problem → Technical Decision → Result** rather than mainly describing what the project does.
- The SpellForge data-modeling decision is a strong signal and should be surfaced directly in the project section.
- The portfolio should clearly distinguish my actual contribution from technologies or features simply used in a project.
- If there are too many technologies or buzzwords, they should be reduced in favour of concrete engineering decisions and outcomes.
- Overall, the impression was positive and technical, but the portfolio could do a better job of proving engineering ability instead of expecting the reviewer to infer it.

---

## Feedback Sorting

### Must-Fix

| Feedback | Action | Status |
|---|---|---|
| Technical strengths should be immediately obvious | Sharpened the Hero section around backend development, data modeling, and system design | ✅ Fixed |
| Projects should show Problem → Technical Decision → Result | Added a consistent proof structure to all five projects | ✅ Fixed |
| SpellForge data-modeling decision should be surfaced | Made the data-modeling decision explicit in the SpellForge project proof | ✅ Fixed |
| Actual contribution should be distinguished from technologies used | Changed the project proof label from `Technical Decision` to `My Contribution` | ✅ Fixed |
| Engineering ability should be proven through concrete evidence | Combined the stronger Hero message with project-level technical proof | ✅ Fixed |

### Nice-to-Have

The reviewer suggested reducing technologies or buzzwords if there are too many and giving more space to concrete engineering decisions and outcomes.

This was treated as a **nice-to-have rather than an immediate must-fix**, because the updated project section already prioritizes concrete engineering decisions and outcomes.

---

## Changes Completed

### 1. Hero Section

The Hero section was rewritten to communicate the technical focus immediately.

It now emphasizes:

- Backend development
- Data modeling
- Future-focused system design
- Scalable and maintainable software

### 2. Project Proof Structure

All five projects now use:

**Problem → My Contribution → Result**

This makes the engineering reasoning and personal contribution easier to identify.

### 3. SpellForge

SpellForge now directly surfaces the XP History data-modeling decision and explains how the structure supports auditability and future features.

### 4. Contribution Clarity

The project proof section now uses **My Contribution** to distinguish personal engineering work from technology labels.

---

## Review Outcome

The review confirmed that the portfolio already communicates a backend-focused, technical impression.

The main improvement was to make the engineering evidence more explicit so that the visitor does not have to infer the technical thinking from project descriptions.
